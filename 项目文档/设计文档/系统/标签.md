## 1. 这份文档是做什么的

增益、事件、道具都需要回答一个问题：**它能影响谁？** 如果每个增益都点名「箭塔、双重箭塔、钢雨……」，新加一座塔就要把所有增益改一遍，玩家也看不出一个增益到底影响多大范围。

标签就是答案：**给每个建筑、单位、敌人贴上若干标签，增益只写「对带哪些标签的对象生效」。**

- 新加一座塔或一种单位，只要声明它的标签，就自动吃到所有旧增益。
- 一个增益写的是一类东西，不是一两个具体对象，符合[随机增益](随机增益.md)「一个增益影响一类东西」的挑选标准。
- 建筑、单位、敌人用同一套标签，经营类建筑（民居、商店、公共建筑）也一样，所以经济增益也能写成「所有商店」「所有民居」。

## 2. 基本规则

| 规则 | 内容 | 状态 |
|---|---|---|
| 多标签 | 一个对象可以同时有多个标签：塔有，单位有，敌人有，经营建筑也有 | 已确定 |
| 写法 | 文档里的标签一律写成 〔标签名〕，用〔〕括起来，一眼能看出这是标签；每个都是超链接，点开跳到它的定义 | 设计提案 |
| 点进去能看到什么 | 每个标签的定义下面列出**哪些对象带这个标签**，以及**哪些增益用到它**。想知道一个标签对应哪些单位、建筑，点开看这一栏就行 | 设计提案 |
| 为什么不用 # 号 | Obsidian 会把 #xxx 当成它自己的标签，点开是全库搜索，不是跳到定义，所以不用 # | 设计提案 |
| 在增益里怎么写 | 直接写在增益的效果里，例如「使用[〔弹道攻击〕](标签.md#弹道攻击)的塔和单位，击中敌人后贯穿而过……」，点标签就能看到哪些对象享受；一句里出现多个标签，表示**同时具备**（取交集）；要排除的写「不含〔……〕」 | 设计提案 |
| 只作用于友方 | 增益只作用于带[〔友方〕](标签.md#友方)的对象；带[〔敌军〕](标签.md#敌军)的对象（所有敌人和野外营地）只用来当条件，例如「目标是[〔被减速〕](标签.md#运行时状态)」「[〔正在拆墙〕](标签.md#运行时状态)的敌军」。写代码时用这两个标签区分，避免把增益加到敌人身上 | 设计提案 |
| 自动继承 | 新对象只要声明标签，就自动吃到已有增益 | 设计提案 |
| 自动带上 | 有些标签是别的标签的「总称」，带子标签就自动带上总称，见「自动带上的标签」 | 设计提案 |
| 推导标签 | 能由数值推出来的标签（[〔重甲〕](标签.md#重甲)、[〔高速〕](标签.md#高速)、[〔巨型〕](标签.md#巨型)）不手填，数值变了自动变 | 设计提案 |
| 状态标签 | [〔被减速〕](标签.md#运行时状态)、[〔低血〕](标签.md#运行时状态)这类是运行时临时挂上的，不是对象本身的属性 | 设计提案 |
| 来源 | 标签最终写在各建筑、单位文档的属性表里；在补全之前，以本文第 4 节为准 | 设计提案 |

**怎么维护**：第 4 节的表格是唯一的数据来源。新增或修改对象后，运行 `工具/标签/link_tags.py`，它会自动做三件事：把 〔标签名〕 变成超链接、把第 3 节每个标签下面的「带这个标签的对象」「用到它的增益」重新生成、检查有没有写错的标签名。**不要手改这两行自动生成的内容。**

## 3. 词表

命名原则：名字本身要说清楚它是什么；同一类的名字风格一致（效果直接用效果名：减速、减甲；状态用「被……」，和效果一一对应；伤害用「……伤害」，攻击方式用「……攻击」）。

## 5. 怎么用

- **增益写法**：直接把标签写进增益的效果里，见[随机增益 第 2 节](随机增益.md)。
- **以后的研究、事件、道具**可以用同一套写法，「开拓者移速翻倍」就是作用于 [〔开拓者〕](标签.md#开拓者)。
- **加新对象时**：先在第 3 节找标签，没有合适的再提新标签。新标签要说明「哪个增益会用到它」，没有用途的不加，避免词表膨胀。
- **标签冲突时的规矩**：
  - [〔魔法伤害〕](标签.md#魔法伤害)的攻击，护甲类增益（破甲箭等）写 [〔物理伤害〕](标签.md#物理伤害) 即可，不用另外排除。
  - [〔魔免〕](标签.md#魔免) 敌人不受魔法效果：作用于 [〔魔法伤害〕](标签.md#魔法伤害) 或 [〔控制〕](标签.md#控制) 的增益对它不生效，增益卡的说明里要写出来。
