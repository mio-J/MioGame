## 1. 适用范围

适用于所有建筑的**建造**和**修理**。执行者都是[开拓者](../单位/开拓者.md)，玩家不需要手动选中某个开拓者，而是由系统**召集最近的开拓者**前去。

## 2. 召集最近的开拓者（已确定）

**建造和修理使用同一套召集规则：**

- 每个建筑都有一个「**修理**」选项。放置新建筑时，也会自动发起建造。
- 发起后，系统召集**离目标建筑最近的开拓者**前去执行。
- **附近没有开拓者时，界面给出提示**，本次操作不生效。

### 2.1 召集细节（设计提案）

| 规则 | 内容 |
|---|---|
| 召集范围 | 以目标建筑为中心 **60 m** 内的开拓者才会被召集 |
| 选择顺序 | 召集范围内**最近的空闲开拓者**（没有在建造或修理的） |
| 全都在忙 | 单栋建造/修理提示「附近的开拓者都在忙」，本次操作不生效、不排队；仅玩家主动创建的休整批量维修采用4.6的有限待办 |
| 距离判断 | 按实际行走距离，而不是直线距离 |
| 提示内容 | 范围内没有开拓者：「附近没有开拓者」 |
| 任务中断 | 开拓者在赶去的途中阵亡，任务回到待分配状态，重新召集 |
| 玩家手动指派 | 玩家也可以手动选中开拓者，直接下令去建造或修理，优先于自动召集 |

普通建造与单栋修理不设排队，玩家发起操作时就知道是否有人前往。休整批量维修是明确显示原因和预算的独立例外，不自动扫描全城。

### 2.2 光圈反馈（已确定）

为了让玩家一眼看出「谁被叫去干活了」，开拓者脚下会出现光圈，颜色表示命令的来源：

| 颜色 | 含义 | 状态 |
|---|---|---|
| **蓝色光圈** | 开拓者收到了**系统召集**（建造或修理），正在前往或执行任务 | 已确定 |
| **绿色光圈** | 玩家**自己选中**并下达移动命令的单位 | 已确定 |

**虚线（已确定）：**被召集的开拓者与目标工地之间会有一条**虚线**，颜色很淡，用来指示他要去哪里。**只有选中该工地（或修理的目标建筑）时才显示**，没选中时不显示，避免同时召集多人时屏幕上线条太乱。

规则细节（设计提案）：

| 规则 | 内容 |
|---|---|
| 虚线颜色 | 与蓝色光圈同色系，透明度很低，不抢眼 |
| 虚线起止 | 起点是开拓者脚下，终点是目标建筑或工地 |
| 虚线显示 | 仅在玩家选中该工地或目标建筑时显示，取消选中即隐藏 |
| 虚线消失 | 开拓者到达并开始施工后消失；任务被取消时同时消失 |
| 蓝色光圈出现 | 玩家发起建造或修理，系统召集到开拓者的那一刻，被召集的开拓者脚下立即出现 |
| 蓝色光圈消失 | 任务完成或被取消（包括玩家手动接管这名开拓者）后消失 |
| 绿色光圈 | 玩家选中单位时显示；下令移动后保持，到达目的地或取消选中后消失。所有玩家选中的单位共用这个颜色，不限于开拓者 |
| 两种同时存在 | 玩家选中了一名正被召集的开拓者时，脚下显示**绿色**（选中优先），同时保留一个小的蓝色标记表示他仍有召集任务 |
| 赶路时手动接管（已确定） | 开拓者在赶去工地的**途中**，玩家手动控制他（下达移动等命令），就**取消这次建造 / 修理**：蓝色光圈与虚线消失，已扣的建造费用全额返还，工地取消；**不会自动召集别的开拓者接手** |
| 只选中不算接管 | 只是选中开拓者、没有下达命令，不算接管，任务继续；下达移动、攻击等命令才算 |
| 取消提示 | 取消时显示简短提示，例如「建造已取消，费用已返还」，避免玩家不知道发生了什么 |
| 施工中不能接管 | 开拓者开始施工后不能被移动，玩家的移动命令无效并提示「开拓者正在施工」；想让他离开，只能取消这个工地（已开工取消返还 50%），见「建造」一节 |
| 附近没有开拓者，或都在忙 | 不会出现任何光圈，只显示「附近没有开拓者」或「附近的开拓者都在忙」的提示 |

### 2.3 海上建筑：召集运输舰（已确定）

开拓者无法在海上行走，所以**海上建筑**（目前是[海上石油平台](能源体系.md)）不能召集开拓者。改为：

| 规则 | 内容 | 状态 |
|---|---|---|
| 召集对象 | 召集范围内**最近的空闲[运输舰](../单位/运输舰.md)**，而不是开拓者 | 已确定 |
| 舰上要有开拓者 | 被召集的运输舰**必须载有开拓者**，没有则不能施工 | 已确定 |
| 施工方式 | 运输舰开到工地旁停下，舰上的开拓者在船上施工；施工期间运输舰**不能移动** | 设计提案 |
| 召集范围 | 与陆上建筑相同，60 m 内（水面距离） | 设计提案 |
| 没有运输舰 | 提示「附近没有运输舰」 | 设计提案 |
| 运输舰上没有开拓者 | 提示「附近的运输舰上没有开拓者」 | 设计提案 |
| 舰都在忙 | 提示「附近的运输舰都在忙」，不设排队，与陆上一致 | 设计提案 |
| 修理 | 海上建筑的修理同样召集载有开拓者的运输舰 | 设计提案 |
| 光圈与虚线 | 蓝色光圈、淡虚线显示在**运输舰**上，规则同 2.2 节 | 设计提案 |
| 手动控制 | 运输舰赶路途中被玩家控制则取消这次建造，规则同陆上开拓者 | 设计提案 |
| 施工中 | 舰上的开拓者不受攻击；运输舰本身仍会被攻击，舰被击沉则施工中断且舰上人员死亡 | 设计提案 |

这意味着玩家想建海上石油平台，必须先有造船厂、一艘运输舰，并把开拓者送上舰，是一条完整的准备链条，也解释了为什么海上石油（+800 能源）是最强也最难拿的能源。

## 3. 建造

| 规则 | 内容 |
|---|---|
| 发起 | 在选定位置放置建筑，立即产生一个**建造工地** |
| 扣费 | 放置时一次性扣除全部成本；未开工取消全退实付资源，开工后取消退实付金币50%、材料不返，见[成本体系](成本体系.md) |
| 施工 | 被召集的开拓者到达工地后开始施工，时间见各建筑的「建造时间」（按 1 名开拓者计） |
| **施工时不能移动（已确定）** | 开拓者一旦开始施工就**不能被移动**，玩家下达的移动等命令会被忽略，并提示「开拓者正在施工」。这样就没有「中途被拉走、进度暂停、还要再补一次」的麻烦，规则也更简单 |
| 施工期间 | 建筑不能使用；开拓者施工时不能移动，且是无敌的；工地可以被攻击，工地被摧毁时开拓者死亡，生命值与被摧毁规则见 3.1 节 |
| 取消 | 开拓者还在赶路、尚未开工时取消，**全额返还**；已经开工后取消，返还**实付金币的50%，材料不返**（与被摧毁相同，避免玩家在工地将被摧毁前取消来拿全额），开拓者随即解除施工状态，恢复可控 |

### 3.1 施工期间被袭击（设计提案）

| 问题 | 提案 |
|---|---|
| 工地能被攻击吗 | **能。**工地和已建成的建筑一样是敌人的目标，遇墙就近拆墙等规则同样适用 |
| 工地的生命值 | 随施工进度增长：**当前上限 = 最大生命值 × （20% + 80% × 进度）**。刚开工只有 20%，完工时 100% |
| 已受的伤害 | 伤害是累计的，进度增长带来的生命值增加不会「抹掉」已受的伤害：受损后继续施工，生命值按上限的增长量同步增加，伤害仍然存在 |
| 护甲 | 与建成后相同，不因施工而降低 |
| 被摧毁 | 工地生命值降到 0 时被摧毁，工地消失，**返还实付金币的50%，材料不返**（与拆除已建成建筑的返还一致，见[成本体系](成本体系.md)），**施工中的开拓者随之死亡**（已确定，见下一行） |
| 开拓者（已确定） | **施工中的开拓者是无敌的**：敌人和范围伤害都打不到他，敌人只能攻击施工中的建筑物；但**建筑物被摧毁时，开拓者才会被杀死**。他也不能被玩家移动，只能继续施工 |
| 救他的办法 | 工地快撑不住时，只能**取消工地**（返还 50%），开拓者随即恢复可控，或者用其他单位、塔去保护工地 |
| 赶路途中 | 尚未开工、还在赶去工地的开拓者**不无敌**，会像普通单位一样被攻击 |
| 工地作用 | 施工中的塔不能攻击，民居不产出，城墙段作为障碍仍然存在，可以挡住敌人，也会被敌人拆 |
| 预警 | 工地遭到攻击时，与已建成建筑一样触发预警提示 |

**示例：**箭塔（300 生命、建造 20 秒）刚开工时只有 60 点生命值，一只普通绿皮 4 次命中就能拆掉；建到一半有 180 点；快完工时接近 300。所以**在敌人来袭前一段时间不要在前线开工**，先把塔建在后方安全的位置。

**代价：**工地被摧毁不仅损失一半费用，还会损失一名开拓者（1000 金币、15 秒重新生产，并占用人口）。开拓者是无敌的，但他和工地绑在一起，这让「在哪儿开工」成为有实际后果的选择。

**为什么这么设计：**
- 施工有风险，玩家会更谨慎地选择开工时机，塔和墙的布防更有策略，而不是随时随地"补塔"。
- 前期建造时间只有 15–30 秒，暴露窗口短，不至于让施工变成陷阱。
- 返还 50% 而不是全部损失，避免开局 3000 金币的时候一次失误就无法翻身，同时保留惩罚。

**只能 1 名开拓者建造（已确定）：**每处工地同时只有 1 名开拓者施工，不支持多人协作加速。想同时建更多建筑，就需要更多开拓者分头去建。这也让开拓者的数量成为一项实实在在的投入。

## 4. 修理

### 4.1 修理选项

- 选中任何**已建成且受损**的建筑，都有「修理」按钮；生命值已满时按钮置灰。
- 施工中的建筑不能修理。
- 修理由玩家主动点击触发，不会自动修理（设计提案）。

### 4.2 修理的表现与计算（已确定）

**修理看起来就是回血：开拓者到场后，建筑的生命值开始逐渐恢复，恢复的同时持续扣除金币。**修理的时间和金币，都按**生命值缺口**的比例计算。

- **只能 1 名开拓者修理**，不支持多人协作。
- 缺口越大，花的时间越长，花的金币越多；缺口为零则不用修。
- 修理过程中金币是**逐步扣除**的，不是开始时一次收清；玩家可以看到金币随着血量一起变化。

### 4.3 费用与速度数值（设计提案）

| 项目 | 规则 |
|---|---|
| 费用 | 生命值缺口 100% 时，费用 = 该建筑**建造成本的 50%**；缺口不足时按比例折算 |
| 速度 | 缺口 100% 时，1 名开拓者满修时间 = max（建造时间，最大生命值÷35），城墙60秒、主城120秒；缺口不足时按比例折算 |
| 回血速率 | 每秒恢复的生命值 = 生命值上限 ÷ 满修时间（城墙2000÷60≈33.33/秒），全程匀速 |
| 金币不足 | 修理暂停，金币够了继续 |
| 只用金币 | 修理只消耗金币，不消耗钢铁等材料 |
| 战斗中 | 可以修理。开拓者不参与战斗，前线修理有被攻击的风险 |

**为什么是 50%：**与[成本体系](成本体系.md)中拆除返还 50% 的规则一致，拆掉再重建总是比修理更贵，不会让「拆了重建」成为最优。

**示例：**

| 建筑 | 成本 | 修满费用 | 修满时间 |
|---|---|---|---|
| 箭塔 | 2400 | 1200（缺一半血则 600） | 20秒（缺一半则10秒） |
| 城墙（每段） | 1000 | 500 | 60秒 |
| 兵营 | 3000 | 1500 | 30秒 |

### 4.4 主城的修理

主城没有建造成本，无法按成本比例计算。提案：每修复 **100 点**生命值花费 **400 金币**，修满 2000 点约 8000 金币；1 名开拓者修满需要 **120 秒**（每秒恢复约 17 点）。主城血量已提高到 2000（见[主城设计](../建筑/经营建筑/主城设计.md)），修理速度和费用之后需要一起复核。

### 4.5 作为金币消耗口

修理费用随建筑规模增加，防线越长、受损越频繁，花费越多。这让金币在后期仍有用处，见[核心玩法循环](../核心玩法循环.md)中关于金币通胀的讨论。

### 4.6 休整批量维修（双主策修改采纳的原型规则）

大波清完的休整期间，玩家可框选一组已建成、受损建筑，查看缺口、当前估算费用与可用工人数，确认本批维修金币上限后创建一次有限任务清单。默认按受损比例降序，同值按确认顺序；可手动重排、删除和取消整批。全基地未分配待办最多12条，已指派任务不占此限额；超出部分显示“未加入”，不隐藏排队。同一建筑不能同时存在两条维修任务，后来受损或新建建筑不自动加入。

每栋最多1工、每工最多1任务，按目标实际行走路径60米内最近空闲开拓者分配；没有人或全忙时显示待分配原因，不从全城自动调工。普通单栋修理按钮仍即时召集，失败提示且不排队。新建建筑仍没有建造队列。

预览不预扣费用，行走与修复速度保持现行规则。实际每笔修复扣费同时计入本批共享预算，并行任务合计不得超过上限；金币不足暂时停修，金币恢复且预算未耗尽时可继续，预算耗尽需玩家明确提高上限或取消。新的战斗伤害会增加实际费用，所以预览是当前缺口的估算，不能保证最终总价。

手动下令接管修理工，或该工人死亡时，停止并解除当前任务指派，该条标记“手动暂停/工人阵亡”，不自动换工人赴险。玩家点重试才重新按60米最近空闲工规则召集。目标拆除或被毁则移除任务；满血完成。取消清单释放未完成任务与工人，已实际修复并扣除的金币不退。修理工仍可受攻击，不继承新建筑施工无敌或施工期间不能移动的规则。

休整结束：**已到场且开始修复**的任务可以继续，仍受本批预算和金币约束；未指派、已指派但仍在赶路的任务都暂停，后者解除工人指派。玩家在战斗中可主动重试暂停任务，但清单不会自动恢复或新增目标。界面始终显示进行、待分配、暂停和完成状态，避免玩家误以为有工人正在前往。

批量功能减少逐墙点选，不提升回血能力。目标是把90秒休整留给修前线、扩矿和调整装备的选择；该规则已采纳用于原型，实现与真人效果尚待验证。

### 4.5 生产设施升本与解锁

升级/兵种解锁为本栋自研，不额外占工人；与招募共用唯一执行队列，同一时刻只执行一项，其他同类设施可并行。全局解锁只执行一次，同一解锁不得在两栋重复扣款。未达到前置的任务不得开始；升级开始扣实际金币材料并预留新增能源，完成转为实际占用。招募仍按既有规则预留人口、按本栋实际等级及装备来源生成单位，旧兵不追溯强化。

未开始的排队任务手动取消或设施被毁时，全退实付资源并释放预留。**已经开始的自研升本/解锁**取消或设施被毁，返实付金币50%，材料不返，不保进度，不授新等级/解锁，释放升级能源增量；取消后建筑保留原等级和原有生命/护甲。未完成招募手动取消或设施被毁均全退实付资源、释放人口/能源预留，不产兵；不能套自研50%规则。已完成全局解锁不随执行设施被毁回滚；本栋被毁等级丢失，重建从1本开始。设施升本期间保留原有生命、护甲、视野和可受攻击状态，不获得工地/工人无敌；暂停本栋招募及其他自研。敌人摧毁已完成建筑不额外发主动拆除退款；升级失败退款仅针对该未完成订单一次，旧已完成投入不得重复返还。修理与主动拆除的基准仅累计已完成等级的实付金币，未完成升级退款后不再进入基准。

## 第二轮原型规则（2026-10-08）

施工无敌只作用于开始施工后的绑定开拓者，赶路仍可被攻击；绑定工人不产生战斗仇恨、不碰撞阻挡敌军，工地仍可被攻击，工地被毁仍杀死工人。修理未被确定为无敌，本轮修理工人保持可被攻击。

只能1人修理、缺口比例计时计费、逐步扣金币保持。满修时间=max(建造时间,最大HP/35)，墙60秒、主城120秒；费用按该建筑当前等级累计实际支付金币的50%×实际修复比例，材料不按标价套现，缺钱暂停。图纸/折扣的实际支付成本是基准，累计升级金币也计入，防止低价建高价修/拆套利。

旧示例的“满修建造时间一半”已废止，新的墙修33.33HP/s；10只普每秒对15甲墙造成88.89HP，净掉55.56，工人不再永远修住10怪。箭塔300HP、建造20秒满修20秒=15HP/s；主城2000/120=16.67HP/s。历史修理时长表不得作实现输入。

## 第四轮修理联账验收

修理与施工必须绑定同一实际开拓者ID，修理者不能同时参与施工；招募、行走、人口和维护实付，赶路/维修仍可受击。每次修复按实际恢复生命和实际支付成本计费，再反馈采购与完工事件；缺钱停工，不能仅在终局补扣一笔而仍沿用旧完成时刻。墙与建筑生命跨阶段连续，禁止按阶段免费满修。当前科技条件样例维修5958.67金反馈后244条事件不变；此前完整回扣会使火炮延迟并导致破墙，说明费用会改变战斗结果。有限休整清单仍按既有12条、60米、玩家预算和手控/死亡暂停规则，不自动赋予无敌或保证修完。
