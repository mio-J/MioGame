## 1. 一天的结构（已实现）

| 项目 | 内容 |
|---|---|
| 一天的长度 | **10 分钟** = 白天 **6 分钟**（360 秒）+ 夜晚 **4 分钟**（240 秒） |
| 游戏钟 | 白天 6:00–18:00，夜晚 18:00–次日 6:00，两段各自压缩进对应的真实时长 |
| 阶段 | 黎明、白天、黄昏、夜晚，共 4 个 |
| 时间轴 | 归一化 0–1：白天占 0–0.60，其中黎明在 0–0.06，黄昏从 0.52 开始；夜晚占 0.60–1.0 |

夜晚比白天短，因为白天要经营，夜晚只是节奏变化，不宜太长。

## 2. 光照（已实现）

| 项目 | 内容 |
|---|---|
| 太阳 | 随时间绕一圈，正午仰角约 62°；颜色由黎明橙红过渡到正午近白，再到黄昏橙红，夜里熄灭 |
| 月亮 | 独立的一盏方向光，永远在太阳正对面；夜里保证有方向光和阴影，物体不会变成剪影 |
| 环境光 | 夜里偏蓝紫，白天偏中性；夜晚保留白天的约 28%，不会伸手不见五指 |
| 光照下限 | 白天阳光强度不低于 0.36，环境光不低于 0.62，避免恶劣天气下画面全黑 |

## 3. 天气（已实现）

天气是叠加在昼夜之上的一组修正，而不是另一套光照。共 5 种：

| 天气 | 能见度 | 表现 |
|---|---|---|
| 晴朗 | 1.00 | 无 |
| 降雨 | 0.75 | 雨丝，地面变湿、出现涟漪和水洼 |
| 雷暴 | 0.55 | 更大的雨，会打闪电，闪电时镜头震一下 |
| 沙尘暴 | 0.40 | 沙尘横向飘过，屏幕蒙上一层霾，移动速度 −35% |
| 浓雾 | 0.35 | 浓雾，远处景物朦胧 |

| 规则 | 内容 |
|---|---|
| 抽签 | 下一种天气按**玩家脚下的湿度和温度**加权抽取：沙漠里几乎不下雨、沼泽里很少沙尘暴，每种天气都有底噪，不会永远只有一种 |
| 过渡 | 天气切换用 22 秒渐变，不是瞬切 |
| 镜头震动 | 全游戏只有闪电会震，其他天气没有持续震动 |
| 界面 | 屏幕上方显示时钟和当前天气，天气切换时右下角弹提示 |

**选址因此有了额外的分量：**在沙漠扎营和在沼泽扎营会遇到不同的天气，这是气候图的自然结果，不需要单独写规则。

## 4. 尚未接入玩法的部分

以下项目在游戏里只是**预留接口**，还没有真正影响单位、建筑或战斗：

| 项目 | 现状 |
|---|---|
| 天气能见度 | 数值已经在天气表里，但视野、警戒范围、塔的射程还没有读取它 |
| 移动惩罚 | 沙尘暴 −35% 已定义，寻路和单位移速还没有读取 |
| 夜间视野 | 夜间玩家单位视野缩小到多少，还没有实现 |
| 哨塔塔灯 | 塔灯的照明范围和夜间效果还没有实现 |

### 4.1 塔射程下限约束（设计提案 · 原型，昼夜接入玩法前不生效）

问题：一旦天气能见度被视野读取，若塔的有效射程取射程与“视野 × 乘数”中较小者，箭塔在雷暴、沙尘、浓雾中只剩约 6.6、4.8、4.2 m，而敌人不受能见度惩罚，弓手仍有 9 m，随机天气会造成“必败窗口”。

约束：**昼夜与天气接入玩法时，塔的有效射程不得低于其射程的 0.8 倍**；处于灯光、哨塔照明或星象殿视野范围内时恢复为全射程。例如箭塔最低 8 m。

以下具体系数仅为**实验**，昼夜接入玩法前不生效，也不作为基线：夜间视野系数 0.75、天气预报（时钟旁显示下一种天气与倒计时）、“视野受限：N 座塔未照明”提示。敌人数值夜间不变，夜晚的压力只来自玩家视野缩小。若试玩里前线建灯成为每局必修，再把下限调到 0.9 或扩大灯的半径。
