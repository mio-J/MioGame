## 2. API Key

**Key 不写在本文档里。**本仓库的远程在 GitHub，key 一旦进入 git 历史就很难彻底删除，所以只记录用法，key 本身保存在仓库之外（例如本地密码管理器）。

2026-09-29 首次尝试时用的 key 曾在对话中明文出现，账户余额为 0。建议在 Tripo 后台重置后再使用新 key。

脚本从环境变量读取 key，不在脚本里硬编码。使用时在 PowerShell 中临时设置，只在当前窗口有效：

```powershell
$env:TRIPO_API_KEY = '<你的 key>'
```

- Key 来自 Tripo 平台的 API 页面（以 `tsk_` 开头）。
- 长期使用也可以设成用户级环境变量。

## 3. 工具脚本

位于 `MioGame/工具/tripo/`：

| 脚本 | 作用 |
|---|---|
| `crop_views.py` | 把合在一张图里的三视图拆成 front / right / back 三张 |
| `tripo_generate.py` | 上传视图、提交多视图任务、轮询、下载 GLB |

流程：

```powershell
py 工具/tripo/crop_views.py "<三视图.png>" "<视图目录>"
$env:TRIPO_API_KEY = '<你的 key>'
py 工具/tripo/tripo_generate.py "<视图目录>" "<输出目录>"
```

## 4. 输入图注意事项

- **每个视角必须单独成图。**多视图接口按单张图理解一个视角，混在一起的三视图不能直接用。
- **拆图不能三等分。**古塞奇尤的披风会越过三等分线，需要按实际位置手工量出切分线（见 `crop_views.py`）。
- **去掉文字标签**（FRONT / RIGHT / BACK），并用相同底色补齐画布，让每张图里人物大小、位置一致。
- **不要用镜像补缺失的视角。**古塞奇尤左右不对称：只有左肩有放射状大肩甲。右侧图看不到这个肩甲，镜像出来的「左侧」也没有，会与正面、背面矛盾，导致肩甲错位或只做出一半。缺少的视角传空对象，让模型自己推断；若结果不准，再单独出一张真正的左侧图。
- 视角顺序固定为：正面、左侧、背面、右侧。正面必须有。
- 需要 A-pose 的造型，方便之后绑定骨骼；概念图中的施法姿态和电弧不要混进输入图。

## 5. 生成参数

| 参数 | 当前值 | 说明 |
|---|---|---|
| 任务类型 | `multiview_to_model` | 多视图转模型 |
| 模型版本 | `v2.5-20250123` | 以 Tripo 当前可用版本为准 |
| 贴图 | 开 | 需要更多积分 |
| PBR | 开 | |
| 面数上限 | 30000 | 即时战略游戏单位面数不宜过高 |

## 6. 生成后要检查的问题

| 检查项 | 原因 |
|---|---|
| 披风与身体是否粘连 | AI 生成的模型常把披风和腿做成一体，影响之后绑定动画 |
| 左肩放射状肩甲 | 结构复杂且左右不对称，容易糊成一块或缺失 |
| 双臂姿势 | 需要接近 A-pose，否则绑定骨骼时手臂会穿模 |
| 头发与立领 | 短发和高领容易穿插 |
| 贴图与设定图颜色 | 金、白、深蓝、红配色是否还原 |
| 面数与比例 | 身高按 1.7–1.8 m，见[距离与移动速度标准](../设计文档/系统/距离与移动速度标准.md) |
